# 架構總覽

> 現況(架構優化階段 6 完成後,2026-07-03)。歷史演進見 `docs/superpowers/2026-07-02-refactor-handoff.md`。

## 三個進入點

Manifest V3 擴充功能,三個獨立的 JS 進入點,分別打包(見 `03_開發與維護指南.md` 的 build pipeline 說明):

- **`src/background.js`**(約 30 行)—— MV3 service worker。僅處理 `chrome.action.openPopup()`、badge 文字/顏色設定、`chrome.tabs.onUpdated`(導航到登入頁時清除 badge)。**資料抓取完全不經過 background**,不做 webRequest 監聽、不做資料儲存。
- **`src/contentScript.jsx`**(約 76 行)—— 注入 `medcloud2.nhi.gov.tw/*`。建立 `#nhi-floating-root` DOM 節點,動態 import `components/FloatingIcon.jsx` 掛載 React 樹;動態 import `apiInterceptor/index.js`(主動抓取引擎,見下節);動態 import `localDataHandler.js`(處理 popup 端「載入本地資料」上傳的 JSON 檔,並註冊 `loadLocalData`/`clearLocalData` 訊息 handler)。
- **`src/popup.jsx`**—— 擴充工具列 popup,掛載 `components/PopupSettings.jsx`,是與 `FloatingIcon` 樹平行、獨立的 React root(不共用 Context,見下方「React 層」)。

## `src/apiInterceptor/` —— 主動抓取引擎

前身是單一 499 行的 `src/legacyContent.js`(名稱是歷史包袱,並非真的「舊版」——它是核心攔截層)。階段 6 拆為六個模組,主檔改名 `index.js`。純主動抓取架構,**不做** XHR/fetch monkey-patch 或被動攔截。

| 模組 | 職責 |
|---|---|
| `index.js`(347 行) | 主檔:初始化、頁面判斷、病患切換偵測狀態機、URL 變化輪詢、`fetchAllDataTypes`/`fetchSingleDataType` 抓取編排、`clearAllData`,匯出兩個開發者 console 除錯 hook(`window.fetchNHI_Data`/`window.getSessionData`,無程式碼依賴) |
| `apiPathMap.js` | `API_PATH_MAP`:14 種資料型別 → NHI API path 的 `Map` |
| `permissionMap.js` | `NODE_TO_DATA_TYPE`:JWT `Permission` 欄位節點 ID → 資料型別對照表 |
| `authorization.js` | 純函數:`getAuthorizedDataTypes(permissions)` 計算已授權型別集合(恆含 `chronicMed`)、`shouldFetchSpecialData(dataType, cloudSettings)` 判斷特殊型別是否該抓 |
| `responseNormalizer.js` | 純函數 `normalizeResponseData(data, dataType)`,把各型別互異的 API 回應形狀統一正規化為 `{ rObject: [...] }` |
| `messageHandlers.js` | `setupMessageListeners(deps)`,以依賴注入方式處理 `chrome.runtime.onMessage`(手動抓取、清除資料、開啟 dashboard、設定變更廣播、匯出病患資料下載) |

執行流程、JWT Permission 節點對照表、慢箋(chronicMed)資料 schema 與 cycle 偵測規則的完整細節記錄在 **`src/apiInterceptor/README.md`**(前身 `src/legacyContent.md`),不在此重複。

**病患識別與授權**:UserID 直接從 `sessionStorage` 的 JWT token 解析(不再掃描 script 標籤或呼叫 `master-menu` API);授權清單直接讀 JWT payload 的 `Permission` 欄位。

## `src/store/` —— 單一真實來源

- **`dataStore.js`**:純 JS pub-sub,取代舊版 15 個 `window.lastIntercepted*` 全域變數。`DATA_TYPES` 常數列出 15 種型別(14 種醫療資料型別 + `masterMenu`)。`setData(type, data)` / `getData(type)` / `clearAll()` / `subscribe(listener)`。`getData` 回傳的是同一參考(非拷貝),消費端不可就地修改。React 端目前仍以 `dataFetchCompleted` DOM 事件驅動更新,`subscribe` 尚無消費者(保留給未來 React 細粒度整合,見 `05_Roadmap.md`)。
- **`nhitwExport.js`**:建置並寫出 `NHITW_DATA` 對外契約,完整格式說明見 `02_NHITW_DATA_對外契約.md`。

## React 層

`FloatingIcon.jsx`(334 行,原 925 行)是 in-page overlay 的組合根,已拆解狀態與副作用到三個 `src/hooks/`:

- **`useUserInfo(open)`**:dialog 開啟時從 JWT token 解析使用者資訊;無 token 時 fallback 讀 `window._localUserInfo`(本地 JSON 匯入寫入)。
- **`useNhiDataState({ appSettingsRef, labSettings, userInfo, setUserInfo })`**:14 個醫療資料 React state + `handleData` 載入管線。`handleData` 呼叫 `dataManager.js#collectDataSources` 從 `dataStore` 讀取原始資料,交給各 processor,結果寫入 state;另外呼叫 `ckmProcessor.processCKMData` 做跨資料源篩選(CKM 摘要)。觸發時機是 `dataFetchCompleted` 事件(而非 `dataStore.subscribe`)——一次批次抓取會對 dataStore 觸發 14 次逐型別通知,事件是「批次完成後單發」語意才正確。
- **`useSettingsState({ open, setOpen, setTabValue, advancedTabIndex, nhiDataRef })`**:`appSettings`/`generalDisplaySettings` state,掛載三種 listener(`chrome.storage` 設定變更、`chrome.runtime` 訊息、`dataFetchCompleted`)。

**`nhiDataRef` 循環依賴解法**:`useSettingsState` 的 listener 需要呼叫 `useNhiDataState` 回傳的 `handleData`/`setGroupedXxx`,但 `useNhiDataState` 需要 `useSettingsState` 的 `appSettingsRef` ——互相依賴。`FloatingIcon` 建立空的 `nhiDataRef`(`useRef(null)`)先傳入 `useSettingsState`,待 `useNhiDataState` 執行完成後,在同一次 render 內把回傳值指派給 `nhiDataRef.current`。`useSettingsState` 內的 listener 一律經 `nhiDataRef.current.xxx` 存取,因為 listener 只在非同步事件觸發時才讀取,此時 `.current` 必定已賦值。**這是既有 `openRef`/`appSettingsRef` stale-closure 修復模式的延伸,勿改回直接閉包引用。**

`MainDialogHeader.jsx`(約 350 行)是 tab 導覽列 + CKD/CT/MRI/過敏/手術/出院狀態指示器,自 `FloatingIcon` 逐字搬出。

Tab 內容在 `src/components/tabs/`(`Overview.jsx` + per-data-type tabs如 `MedicationList.jsx`/`LabData.jsx`/`ImagingData.jsx` 等;`Overview_*.jsx` 是 Overview 內的分區卡片,如 `Overview_ImportantMedications.jsx`/`Overview_LabTests.jsx`/`Overview_IntegratedHealthData.jsx`)。popup 使用 `src/components/settings/` 的平行設定樹(`AdvancedSettings.jsx`/`MedicationSettings.jsx`/`LabSettings.jsx`/`ChineseMedicationSettings.jsx`/`GeneralDisplaySettings.jsx`/`OverviewSettings.jsx`/`CloudDataSettings.jsx`/`DataStatusTab.jsx`/`LoadDataTab.jsx`/`AboutTab.jsx`)。

### Settings / Context

所有使用者設定存於 `chrome.storage.sync`。單一事實來源是 `src/config/defaultSettings.js`;`src/config/settingsSchema.js` 由它自動衍生 52 個 storage 扁平鍵(含歷史改名對照)與扁平↔巢狀 `{ western, atc5, chinese, lab, overview, general, cloud }` 的映射,供 `settingsManager.loadAllSettings`、各設定變更 handler 與設定 UI 元件共用。新增設定的 SOP 見 [`Settings.md`](./Settings.md)。

`src/contexts/SettingsContext.jsx` 提供 `SettingsProvider` + `useGeneralDisplaySettings()`/`useAppSettings()` hooks,取代逐層 prop 傳遞(Provider 掛在 `FloatingIcon.jsx`)。無 Provider 時 hook 回傳 `DEFAULT_SETTINGS` 對應的 fallback 值,確保 popup 樹(不掛此 Provider,有自己的 state)呼叫時仍安全。**例外**:`CKMSummaryBar`(`src/components/tabs/ckm/CKMSummaryBar.jsx`)目前仍透過 `gds` prop 接收顯示設定,尚未遷移到 hook(見 `04_技術債追蹤.md`)。

## Processor pattern

每種**要顯示**的醫療資料型別在 `src/utils/` 有一個對應 processor(`medicationProcessor.js`、`labProcessor.js`(薄轉發層,實作在 `labProcessorModules/`)、`chineseMedProcessor.js`、`imagingProcessor.js`、`allergyProcessor.js`、`surgeryProcessor.js`、`dischargeProcessor.js`、`medDaysProcessor.js`、`patientSummaryProcessor.js`、`cancerScreeningProcessor.js`、`adultHealthCheckProcessor.js`、`hbcvdataProcessor.js`),各自輸出一個 singleton,主方法 `process<Type>Data(raw, settings)` 把 API 的 `rObject` 陣列轉成 UI 可用的結構。

`src/utils/dataManager.js` 是唯一的 dispatcher。`handleAllData` 用一個宣告式的 `PROCESSOR_REGISTRY` 陣列(`{ sourceKey, guard, run, setterName, resultKey, useSafeSetter? }`)搭配單一迴圈執行全部 12 個 processor(取代原本 12 段幾乎相同的樣板),新增一個顯示型資料型別只需加一筆註冊表項目。

**兩來源合併模式(目前唯一案例:`chronicMed`)**:`chronicMed` 沒有專屬 processor 或 UI tab,而是併入 `medicationProcessor.processMedicationData(rawMedication, rawChronicMed, formatSettings)`,讓慢箋(連續處方箋)紀錄併入西藥列表/表格顯示。合併處理三種情況:(a) 原處方箋比對既有 medication.rObject 紀錄(附註,不重複列);(b) 藥局續領合成新的「藥局」visit group;(c)「效期內」(已開立、尚未進入續領週期)處方箋附註不同顏色的 Chip。cycle 偵測語意與 `sort_code` 欄位定義記錄在 `src/apiInterceptor/README.md`(「慢箋資料 schema 與 cycle 偵測規則」節)。新增類似的兩來源資料型別時應沿用此模式,而非另建平行 processor。

`processMedicationData` 第三參數 `formatSettings` 攜帶使用者的自訂複製格式設定;為 `null` 時(如舊呼叫端)內部 fallback 讀 `chrome.storage.sync`。**不存在** `window.medicationFormatSettings` 側通道——設定一律以參數傳入(階段 5 移除)。

`labProcessor.js` 只是把實作轉發到 `src/utils/labProcessorModules/`(`abbreviationUtils.js`/`customReferenceRanges.js`/`deduplicationUtils.js`/`formattingUtils.js`/`groupingUtils.js`/`referenceRangeUtils.js`/`tableUtils.js`/`valueUtils.js` + `index.js` 主檔)。

## copyFormat config 驅動編輯器

西藥/檢驗的「自訂複製格式」編輯器共用一套實作於 `src/components/tabs/copyFormat/`:`FormatElementsPanel.jsx`、`useFormatEditorState.js`、`FormatPreview.jsx`、`dragDropHandlers.js`(通用邏輯與 UI),差異(可用元素、預設值、`chrome.storage` key、預覽渲染)由 `medicationConfig.jsx` 與 `labConfig.jsx` 注入。階段 5 之前這是兩個近乎複製的目錄(`medicationCopyFormat/`、`labCopyFormat/`,合計約 3,498 行),已合併刪除,淨減約 1,693 行。新增格式元素或新的可複製資料型別時,改對應 config,不改通用模組。

## 型別安全網

階段 6 新增:`jsconfig.json`(`checkJs: false`,只有明確 `// @ts-check` 的檔案才做型別檢查)+ `typescript` devDependency + `npm run type-check`(`tsc -p jsconfig.json --noEmit`)。`src/types/processors.js` 集中定義所有 processor 輸出的 JSDoc `@typedef`(`MedicationGroup`/`LabGroup`/`AllergyItem`/`SurgeryItem`/`DischargeItem`/`ImagingResult`/`MedDaysItem`/`PatientSummaryItem`/`ChineseMedGroup`/`CancerScreeningResult`/`AdultHealthCheckResult`/`HbcvResult`),12 個 processor 的主方法都補上 `@returns {import('../types/processors.js').Xxx}` 註記(僅文件化 + 編輯器 intellisense,不影響 runtime,也未對大檔案開啟 `// @ts-check`)。
